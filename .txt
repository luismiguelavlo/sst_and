# Auditoría y corrección de módulos Excel SG-SST

## Resumen ejecutivo

Se identificaron y corrigieron **3 patrones vulnerables** presentes en **15 módulos** con importación masiva Excel:

1. **Worker Resolution Collision**: `resolveWorkerId` buscaba por código antes que por documento, causando falsos matches cuando cédulas coincidían con códigos cortos (`"1"`, `"2"`, `"3"`) en la base de datos.

2. **Folio False Matching**: Números de fila en plantillas (`1..9999`) eran tratados como folios válidos de negocio (e.g., `AT-2026-001`), causando actualizaciones de registros incorrectos.

3. **Date & Number Parsing**: `excelDateToIso` no soportaba seriales numéricos de Excel (25000-60000), fechas `M/D/YY` vs `D/M/YYYY`, ni cédulas en notación científica (`1.088e+9`).

## Cambios aplicados

### 1. Centralización de `resolveWorkerId`
**Archivo**: `lib/sg-sst/workers/repository.ts`

```typescript
export async function resolveWorkerId(ref: string): Promise<string | null> {
  const trimmed = ref.trim();
  if (!trimmed) return null;

  const digits = trimmed.replace(/\D/g, "");
  // Cédulas (≥5 dígitos): buscar por documento primero
  if (digits.length >= 5) {
    const byDoc = await findWorkerByDocumentNumber(trimmed);
    if (byDoc) return byDoc.id;
  }

  // Fallback: buscar por código
  const byCode = await findWorkerByCode(trimmed);
  if (byCode) return byCode.id;

  if (digits.length < 5 && digits.length > 0) {
    const byDoc = await findWorkerByDocumentNumber(trimmed);
    if (byDoc) return byDoc.id;
  }

  return null;
}
```

**Rationale**: Priorizar `findWorkerByDocumentNumber` para referencias con ≥5 dígitos evita colisiones con códigos cortos (`"1"`, `"2"`, `"3"`, `"99"`) almacenados en `sst_workers.code`.

### 2. Helper `isBusinessFolioCode`
**Archivo**: `lib/sg-sst/draft-mode.ts`

```typescript
export function isBusinessFolioCode(value: string | null | undefined): boolean {
  if (!value) return false;
  const trimmed = value.trim();
  if (!trimmed) return false;
  
  // Si contiene letras o guiones, es un código de negocio
  if (/[a-z\-]/i.test(trimmed)) return true;
  
  // Si es solo dígitos, solo es válido si es >9999
  const numValue = parseInt(trimmed, 10);
  return !Number.isNaN(numValue) && numValue > 9999;
}
```

**Uso**: En `actions.ts` de cada módulo:

```typescript
const existing =
  row.folio && isBusinessFolioCode(row.folio)
    ? await findXByFolio(row.folio)
    : null;
```

**Rationale**: Prevenir que números de fila en plantillas (`1`, `2`, `3`, ..., `9999`) sean tratados como folios válidos de negocio.

### 4. Chunk Imports Configuration
**Recomendación**: Ajustar `chunkSize` y `continueOnChunkError` en `runChunkedBulkImport` según peso de procesamiento por fila:

- **Bajo** (lectura simple): `chunkSize: 25, continueOnChunkError: true`
- **Medio** (actualización + validación): `chunkSize: 15, continueOnChunkError: true`
- **Alto** (generación secuencial de códigos + workflows): `chunkSize: 8, continueOnChunkError: true`

**Ejemplo** (`accidentes`):
```typescript
const result = await runChunkedBulkImport(
  preview,
  (chunk) => bulkImportAccidentsAction({ rows: chunk }),
  {
    chunkSize: 8, // Por generación de AT-2026-XXX + auto-investigations
    continueOnChunkError: true,
  },
);
```
